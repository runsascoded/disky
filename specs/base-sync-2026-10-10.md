# Base sync 2026-10-10: `[cloud]` commits on `gcs` / `cw-s3` vs `cloud`

**Status:** done. Audit only: **nothing needed picking**. Every `[cloud]` (and `[base]`) commit that `git cherry -v cloud <branch>` reports as missing is already on `cloud`, obsolete, or deployment-specific.

## Why `git cherry` over-reports

`git cherry` matches by patch-id, and almost every base pick was adapted while picking: different context, conflict resolution, fixtures scrubbed for the public repo, gcs-lineage tests re-expressed on `migrations/cw`, and so on. A pick's patch-id then differs from its original, so `git cherry` lists the original as missing even though `cloud` carries it with a `(cherry picked from commit …)` trailer. Of the 114 `[cloud]`-tagged gcs commits and 31 cw-s3 commits it lists (at `cloud` = `487058b4`, then `db14f7ef` (a spec-only commit); `gcs` = `4c2661f5`, `cw-s3` = `4de39d7d`):

| branch | listed `[cloud]` | `-x` trailer on cloud | same subject, no trailer | no match on cloud |
|---|---|---|---|---|
| gcs | 114 | 85 | 3 | 26 |
| cw-s3 | 31 | 26 | 3 | 2 |

## Method

1. **`-x` / subject match.** Each listed commit is matched to a `cloud` commit by its `cherry picked from commit` trailer, or else by an identical subject. Each pair was then **diffed by content**: every `+`/`-` line of the original must appear in the cloud commit's diff, and both must touch the same files. 137 of 149 pairs are line-for-line identical. The other 12 are deliberate adaptations, noted in the tables below. No pair dropped real base behaviour.
2. **Still on the tip?** For every matched commit, the original's added lines were checked against `cloud`'s current tree. Where few remain, a later `cloud` commit deliberately rewrote or removed that code (also noted below). Examples: `/api/prefix-stats` → `/api/prefixes` (`6f39e858`); `cw_digest.py` → `digest.py` (`ae8d2183`); a modules-only store registry (`5ca5ab18`); the mark routes dropped (`654aaef9`); Slack mentions removed (`1ca7627f`). None of these is a lost pick.
3. **No match.** The 28 tagged commits with no match, and every **untagged** commit touching `site/src`, `site/functions`, `cloud/src`, `src/` or `packages/` (110 of them), were classified by hand. Supporting evidence: the share of each commit's added lines found verbatim in `cloud`'s copy of the same file, plus a grep for the feature's identifiers. Almost all the gcs untagged ones are the static-names / static-roots / map-filter and ClickHouse work. That arrived on `cloud` as one fold, `9f124c20` ("the static name pipeline, the ClickHouse store and serving box, and the static `/names` + map filter, from `daily-append`, `ch-store`"), and the ClickHouse / box half was later removed (`20f57b46`, merge `c41a5778`, tag `ch-store-final`).
4. Untagged commits touching only CI, `job/`, `deploy.env`, `cloud/tests/test_*_cw_config.py`, goldens or store modules are deployment config and were not listed one by one. Spot-checked: none is generic.

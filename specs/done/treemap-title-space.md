# Reuse empty branch title space

Implemented and deployed to OA R2 dev and production on October 13, 2026. The core remains opt-in for other consumers.

Ryan's OA R2 screenshot shows wide parent bars whose label/size occupy only the left side. The deployed DOM and canvas layouts both reserve a uniform 20 px strip. No prior implementation was found in this repository's shared-core or older UI history; root has no concurrent layout edits.

Add an opt-in `reclaimTitleSpace` core prop and enable it on the R2 site. Measure the rendered title font/padding once per map; conservatively reserve enough width for both DOM and canvas text. A branch with right-aligned size or arbitrary subtitle content retains its full-width title strip. Truncated long labels also retain the space they actually require.

Find a complete vertical partition to the right of the title: no child rectangle may cross it. Reclaim the strip using one common area multiplier across every sibling. Right-column tiles grow vertically and narrow horizontally; left-column tiles widen while remaining below the title. Keep original sibling area ratios, relative heights, shared boundaries, parent/child bounds, nesting and hit tests exact. If there is no complete partition, keep the existing geometry. Shared and gaps modes respect their own outer insets. Shrink the parent's title hover area when columns are raised.

DOM placement, canvas placement, outlines and exports must use the same reclamation helper. Verify exact geometry, hit testing, no crossing/overlap, collapsed-chain labels, long/right-aligned titles, both renderers and real OA R2 rendering. Deploy after tests and browser verification. Other deployments retain the core default until their owners opt in.

The shared `layoutChildren` helper uses an O(n log n) complete-partition search. Font probes reproduce the cell's CSS ancestry and reserve tabular numeral widths as well as both renderer fonts. Right-aligned sizes and arbitrary subtitle content conservatively retain full-width titles. The initial rollout incorrectly stretched only the right-hand partition. Ryan identified that as a bug: reclaimed pixels must be included in the common area scale. An exact regression failed before the fix (left multiplier 1, right multiplier 1.25) and passes with a common multiplier 25/23. The fix preserves the base layout's area ratios, including any explicitly configured remainder-legibility allocation; it does not remove unrelated nested-header/gutter costs.

For body width W, body height H, old partition B and reclaimed height L, the common area multiplier is W(H+L)/(WH+BL). Left x/width scale by that multiplier; right x/width scale by its product with H/(H+L), while right y/height scale by (H+L)/H. The new partition moves right, stays clear of the measured title, and total child width remains W. All children receive the same area gain per unit of their original area.

Initial rollout validation: 180 core tests passed, including exact column bounds, crossing rejection, shared/gaps insets, collapsed labels, reclaimed hit tests and component DOM/canvas equivalence, but those tests failed to require equal sibling area multipliers. Preview `c2596364` and production `d8820a6d` used the incorrect stretch-only geometry.

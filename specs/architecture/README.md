## The present decision

Production still runs the serverless architecture. Its Pages source metadata reports `3d0a4fa`, matching `gcs-prod`, but the deployed GCS site also includes uncommitted changes: that SHA is not the complete built-source identity. Auth-gated Pages release **`8404e950`** adds accepted **Oct 6 root summaries** to [stitched name search][dev-names]. Oct 4/5 retain catalog lookup or bounded name-posting fallback; Oct 6 now qualifies literals from its own T100k/L16 census (48,748). Until a cold fallback exists, it serves a 71,273-literal superset (`438e6615…`, per-date qualification in the registry), so no previously answered literal regresses. Generations `98955269…` (own-only) and `f07bc80b…` (inherited union) are retained. Dated comparisons align bucket paths and retain independent source positions. Chrome verifies paired maps/tables, baseline removal and no-baseline reload; unavailable new-date queries display no fabricated zero table. The separate [catalog-only viewer][dev-hot] retains prepared bucket-child detail for frozen Oct 4/5. This is not a faster implementation of every rich-search field, and is not released to production. Prepared children cannot be drilled further.

The strongest demonstrated broad-query direction is aggregate-first serving: account for every matching byte/count, discover bounded heavy children, and fold the rest into an exact remainder. Tens of millions of matches need not become tens of millions of response rows. Directory-hit coverage does not invent matching-path counts. The dev backend publishes **71,182 T100k/L16 predicates** as a dated Oct 4/5 union, with both native L1 catalogs and artifact-bound prefix-closure proofs. **All 71,182 L1 HTTP two-date diff bodies** equal the pinned reader's whole bodies without stripping fields. Full L2 extends the initial five-query bucket-detail release `8254998f`; the earlier copy-only `14c4c3bc` checkpoint passes **853 tests with one skip** and post-deploy exact-table/zero-result checks. Current stitched release acceptance is recorded below. Prepared bucket-root detail has no deeper child drill, owner filters or daily refresh. The quick tunnel is not a durable service guarantee. Arbitrary drill detail, Boolean/owner/age semantics and full historical object coverage remain separate gates.

An all-history RAM node is plausible enough to evaluate, not proven to fit or win. The alternative-design envelope estimates 64.5–82.8 GB for only selected historical components; it excludes substantial indexing, build/update, query and recovery headroom. Earlier 0.20-second ClickHouse results measured roots/totals rather than complete rich treemaps. Neither number should be used as a production sizing or latency promise.

The **hosted dev backend serves T100k/L16 L1 and full paired L2** on frozen Oct 4/5; production remains unchanged. The full v2/TCP L2 build exits 0 without OOM in **3,368.125 seconds stream / 3,402.164 seconds build**, retaining **701,754 cells** in a **211,480,689-byte artifact**, not fleet usage or a serving-memory bound. Complete accepted-subset parity and all covered-control frames plus four scoped independent checks pass; **119 remote fixtures pass in 4.61 seconds**. Activation at **07:42:11 UTC** preserves flags and resolves transient startup 503. **All 427,092 complete L2 diff responses** (71,182 × six buckets) equal the pinned reader, exit 0/no OOM at **07:52:15 UTC**. Benchmark elapsed time is **431.303 seconds excluding catalog load**; same-node median/p90/max are **0.726/0.807/11.306 ms**, maximum body **12,606 bytes**, uncontrolled caches—not independent source truth, edge latency or an SLA. Backend RSS is sampled at approximately **1,807,636 KiB**, not a peak. Copy-only Pages `14c4c3bc` and post-copy Chrome checks pass. Construction/proof history is in [the short-query plan][short-query].

Heavy latency benchmarks remain serial on the existing eight-core VM; independent implementation/review/docs can run in parallel in disjoint files or worktrees. `wt/ch-store` owns backend/catalog code and these docs; `wt/coarse-beta` retains the locally verified `/hot` implementation alongside parked coarse changes. `wt/hot-preview` isolates the shipped release: the existing `wt/gcs/site` tracked/untracked snapshot at base `3d0a4fa9`, with `/hot` and later `/names` additions. Its pre-change JS/CSS are byte-identical to the previously deployed assets; source hashes and build/deploy/test logs are retained under its ignored `tmp/`. All releases target branch `dev` only, with dirty-source provenance explicit. `gcs-prod` is a source pointer, not the dirty deployment's full identity. Root `git status` does not show nested-worktree changes. The main dev backend's hot and stitched lanes are live; the obsolete standalone service is stopped with artifacts retained. No commits, push or production deployment were made for this rollout.

Six fresh normal-plan seam trials cover three literals on both frozen dates. A directory-heavy unregistered case builds in **0.1295/0.13475 seconds**, agreeing with complete independent full-path oracles taking **29.9966/29.4236 seconds**. Two near-T cases agree with accepted native catalogs and build in **0.6359/0.7938** and **1.68679/1.81816 seconds**, despite nearly identical direct-hit counts. Their CH query-log reads differ substantially: approximately **26.05M rows / 1.23GB** versus **139.44M rows / 5.21GB**, not physical disk I/O. These six single uncontrolled-cache trials show no gap on the tested samples, not percentiles or a universal threshold policy. **119 focused remote checks pass, including 19 native fixtures**.

The stitched `/api/name-summary` + `/names` lane is now **live on dev**, still opt-in/default-off elsewhere. Caps are **200K names / 100K postings / 100K outer roots**, with a **five-second combined-diff compute budget**. Cold concurrency is one, hot concurrency two; excess work fails without queuing or partial/zero results. Owned-query cancellation and strict temporary cleanup retain the slot until quiescent, quarantining uncertain cold state. **138 remote fixtures pass in 6.01 seconds with no skips**, including actual fractional deadlines and timeout/KILL cleanup. **101 checker fixtures pass remotely in 2.95 seconds**; **30 complete HTTP bodies** (five queries × three trials × single/diff) match pinned catalog or independent cold controls, normalizing only four validated stage timings. Directory-heavy cold median is **124.244 ms single / 237.300 ms paired**; registered median ranges are **0.738–0.859 / 0.837–0.983 ms**. These are same-node uncontrolled-cache checks, not edge SLAs or a full-source oracle. **930 site tests pass with one skip**, both type checks and build pass; Chrome verifies on-demand/catalog switching and catalog-only bucket navigation. No immediate browser-disconnect cancellation is claimed. Production and ordinary routes are unchanged.

The completed sweep used the existing node serially: four threads, 8 GiB query memory, 8 GiB spill and a cumulative 500K-pattern cap. Shared minimum-T tables yield the T100k/300k/1M × L7/12/16 grids without nine duplicate enumerations per date. The coordinator exits successfully and is inactive; source sync waited for all censuses to finish. Native fixture acceptance passes. The real pruning screen retains **86% of names** and costs **48.849 seconds** before length 8 takes **69.737 seconds**, versus the control's **71.201 seconds** for that layer. This uncontrolled-cache screen does not justify the added pruning pass; that direction is set aside. No new VM/GCP Batch job or accepted-catalog overwrite is involved. Details and the pending owner design are in [the short-query plan][short-query].
